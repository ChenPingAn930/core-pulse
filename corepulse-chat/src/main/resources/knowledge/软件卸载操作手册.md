## 一句话理解卸载

> 一个软件 = 安装目录 + 一堆"写着它地址"的引用（注册表卸载项/服务/文件关联/启动项/快捷方式）。
> **正确卸载 = 用软件自带的卸载器，把程序和引用一起清理干净。**
> 直接删文件夹 = 程序没了，但引用全残留：卸载列表还有它、服务还在、文件关联还指向它 → 系统越来越脏。

**核心原则：**
1. **先调查再用对方式** —— 搞清楚它怎么装的、卸在哪个目录、有没有用户数据、有没有内置驱动，再动手。
2. **通用走自带卸载器** —— 绝不直接删目录（那会留一堆残渣）。
3. **卸载＝彻底删除** —— 主程序、卸载项、注册配置键、AppData 用户数据/缓存/更新器、开机自启、服务、计划任务、快捷方式，一个不留。只有用户卸载前明确说"保留我的数据/配置"才留，否则默认全部清掉。
4. **卸载后必验证 + 清残留** —— 查程序没了、残留清了、空间释放了。

## 一、适用场景 / 卸载前的核查（先查再动）

**禁止凭印象说"这软件能卸/不能卸"、禁止一上来就删目录。先查这 4 件事：**

| 查什么 | 为什么 | 命令 |
|---|---|---|
| 1. 安装目录 & 卸载器在哪 | 很多软件自带卸载程序，用它删最干净 | 见 2.1（注册表最准） |
| 2. 是哪种包（NSIS/Inno/MSI/绿色） | 决定静默参数 | 见 2.2 |
| 3. 软件在跑吗？ | 正在运行的软件卸载会被锁，必须关闭 | `tasklist \| findstr /i 软件名` 或服务 `sc query \| findstr /i 软件名` |
| 4. 有什么用户数据？ | 卸载器会问要不要删用户数据 | 见 2.3 |

## 二、怎么查（一致流程）

### 2.1 查安装位置 + 卸载程序（注册表最准，**64 位与 32 位注册表都查**）

```bash
reg query "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "软件名"
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "软件名"
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "软件名"
```

关键字段：
- `UninstallString` ← 卸载程序路径，最重要
- `DisplayName` 确认是哪个软件
- `InstallLocation` 装在哪个目录
- `QuietUninstallString` 有些软件提供静默卸载命令，有就优先用

### 2.2 判断包类型（决定静默参数）

| 包类型 | 静默卸载参数 |
|---|---|
| NSIS（国产很多） | `卸载.exe /S` |
| Inno Setup | `卸载.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART` |
| MSI | `msiexec /x 包的路径.msi /qn` |
| 绿色软件（免安装） | 没有卸载项，直接删目录+关联 |
| 办公/Adobe/AMD 等大件 | 用官方专用卸载器 |

> 不确定软件是否支持静默卸载，先跑 `卸载程序.exe /?` 看帮助，或交给用户手动点完向导（卸载很快），不要硬猜参数把电脑搞崩溃。

### 2.3 查用户数据（纳入清除范围，默认一并删）

```bash
dir "%APPDATA%\软件名" "%LOCALAPPDATA%\软件名"
```
这些可能是配置、登录态、缓存、聊天记录。**记录位置并告知用户，默认不删，让用户决定；除非用户明确说全删。**

### 2.4 查「软件自带的内置设备/远程驱动」（远程/摄像头/虚拟类软件必查）

某些软件随安装带自己的虚拟设备驱动：**远程协助软件（ToDesk / 向日葵 / TeamViewer 等）的虚拟摄像头、虚拟显示器、虚拟 USB、虚拟手柄**，以及录屏/虚拟设备类工具。

- 这一类**不是普通的"软件目录"**，是**注册成系统驱动的一部分组件**，**卸载器常常只删主程序、漏删驱动**。
- **判断方法**：软件安装目录下往往有 `drivers\`、`*.sys`、`*.inf`、`*.cat` 子目录/文件。一旦有，就要按"带驱动/虚拟设备"对待（B 类），卸载后必须单独追着清理。
- ⚠️ 注意：这些属于**应用内置驱动，应该随软件一起卸**，不要误归类到"系统驱动不可卸"的里面。（区分见第三章/四）。

## 三、判断：能不能卸？（三类分级）

| 级别 | 能卸吗 | 说明 |
|---|---|---|
| **A 可放心卸** | ✅ 直接卸 | 不用的浏览器旧版、小工具、小游戏、命令行工具 |
| **B 谨慎卸** | ⚠️ 卸之前确认 + 提示风险 | 杀毒（驱动自保护）、**带内置虚拟/远程设备的软件（驱动要一起清）**、深度绑定登录态的软件 |
| **C 绝对不卸** | ❌ 拒绝 + 解释 | Windows 系统组件、**系统核心/硬件驱动**、杀毒核心、用户依赖的办公套件、UWP 系统应用、`C:\Windows` 下的内容 |

> **区分 B/C 边界：** C 类的"驱动"指**系统/硬件驱动**（如显卡驱动、内核核心），卸了系统崩/安全裸奔。B 类的"带驱动软件"指**应用自己装的小虚拟驱动**（如 ToDesk 的虚拟摄像头/USB），它属于该软件，卸载时应一起清——**不要因为带着"驱动"两个字就拒绝卸，也不要对系统驱动误当软件乱卸。这条是 v1.1 强调点。**

**铁律：系统级驱动 / 硬件驱动 / 系统组件不能卸**，遇到 C 类直接拒绝并说明原因。

## 四、正确卸载（按类型）

### 4.1 通用（优先）——用自带卸载器
**方式A：读注册表得卸载器直接运行（AI 可自动）**
```bash
"C:\路径\卸载软件.exe"
```

**方式B：调控制面板**
```bash
control appwiz.cpl   # 弹 GUI，不推荐 AI 自动
```

**方式C：静默卸载（AI 可全程自动）**
```bash
# NSIS
"C:\路径\卸载.exe" /S
# Inno
"C:\路径\卸载.exe" /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
# MSI（用注册表拿到的包路径）
msiexec /x "C:\路径\某某.msi" /qn
```
静默卸载常见坑：
- 用 `"卸载.exe" /S start /wait`（bash 里用 `start /wait` 让它等卸载器结束，否则像后台就跑）——**确保卸载真正完成再做下一步**。
- MSI 卸载返回码：1605 表示"不在系统中（已卸载）"，3010 表示"已卸载但标签重启"。返回码 0 = 成功。

### 4.2 绿色软件（免安装，无卸载项）
走"迁移"流程（见《软件迁移操作手册》），先迁移/备份再删目录，别在无卸载项时硬删注册表。

### 4.3 大件（办公/显卡/专业软件）
**用官方专用卸载器**（注册表或官网给），很多带"清理残留"步骤。不要删目录。

### 4.4 卸载前：先建档（基线对比，卸载干净度检查识别）【v1.1 新增】

> **为什么**：很多"卸不干净"不是卸载器技术差，而是**事后只查不知道该漏了哪**。把面前软件"足迹"先在机器上建档，卸载完再重跑一遍对比，**卸载时在的、卸载后还在的那就是残留**，一个都不漏。

卸载**前**逐项记录（AI 自动收集）：

| 层 | 记录什么 | 命令/查法 |
|---|---|---|
| 1 进程 | 软件进程及 PID | `tasklist \| findstr /i 软件名` |
| 2 服务 | 服务名/启动类型(AUTO/MANUAL)/路径 | `sc query state= all` 后搜软件名 |
| 3 安装目录 | 整棵文件树（每个文件大小 + 哈希指纹） | `dir /s` 后对关键 exe/dll 计算 MD5 |
| 4 注册表层 | `Uninstall\软件名`、`HKLM\SOFTWARE\软件名`、`WOW6432Node\软件名`、`HKCU\SOFTWARE\软件名`、`Services\软件名` | `reg query` 或注册表枚举 |
| 5 内置驱动 | 驱动目录文件与驱动注册服务 | 见 2.4/4.5 |
| 6 计划 | 有无 | `schtasks /query /fo csv /ns` 搜软件名 |

卸载后把以上重跑一遍，**"卸载前有、卸载后还有"的表就是残留**，逐条清理。

> 本例实战：卸载 ToDesk 时靠"安装目录整树 MD5 + 各注册表层建档 → 卸载后重跑对比"，抓到了卸载器漏删的 `HKLM\SOFTWARE\ToDesk` 设备身份键。

### 4.5 带内置驱动/虚拟设备的软件（远程/摄像头/虚拟类）
卸载主程序后，还要清除驱动部分：
1. 驱动文件目录（如 `C:\Program Files\ToDesk\drivers\`，含 `.sys/.inf/.cat`）随主目录一起清。
2. 检查对应驱动服务：
   ```bash
   sc query state= all | findstr /i "驱动名 软件名"
   ```
   有就 `sc stop` + `sc delete`（需管理员，见 6.1 权限提示）。
3. 卸载完刷新设备管理器，确认没有出现"未知设备/感叹号/幻影"残留。
> 若卸载后仍有隐藏驱动服务进程捣乱 → 提示用户别慌，官方卸载器一般带"修复卸载"，或引导先停服务再清理。

## 五、卸载时问你"要删用户数据吗？"
- 默认＝**连同用户数据一起删**（卸载＝彻底卸载，什么都别留）。
- 只有用户**卸载前明确说"保留我的数据/配置，别动 AppData"**时，才把用户数据目录留下，但要把其位置与大小明说清楚。
- 只要目标是"卸载干净"，AppData/缓存/日志/更新器就默认一并删，删完复检到空。

## 六、卸载后：清理残留 & 验证（必须做）

### 6.0 卸载后必做：立即验收并主动汇报「干净/不干净」（禁止等用户追问）

> **铁律：** 卸载程序跑完**必须立刻做实际残留检查，并主动把结论告诉用户**——绝不是回答一句"已卸载"就结束，然后等用户追问"卸载干净了吗"才回头去查。
> 本手册要求：**每次我最终回复的结尾一定要输出「干净/不干净 + 残留清单」的验收结论；没给结论就不算完成。**

> **检测方式（铁律）：绝不允许只用 `dir "%APPDATA%\软件名"`、`reg ... /f "软件名"` 这种"按软件名死抠单个目录/键"来判"无残留"**。实测残留目录名常和软件名毫无关系：卸载"沙漏"，残留却是 `com.libxcc.ShaLou`、`crosshair-tool`、`com.libxcc.xcc-rundll`——跟"沙漏"两个字都对不上，按名死搜必漏还误报"无残留"。
> **正确做法＝快照 diff**：卸载前把 `%APPDATA%`、`%LOCALAPPDATA%`、`%PROGRAMDATA%` 下的目录各录一份当基线；卸载后再列一次对比，抓到多出来/仍存在且带厂商特征名（`com.<厂商>.xxx`、`<软件缩写>-updater`、无关缩写）的目录 → 那就是残留，无论叫什么都必须挖出来并清理。

卸载后直接重跑以下全键检查（残留与否看有没有输出），把命中项全部抓全：

```bash
# ① 卸载项是否残留
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "软件名"
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "软件名"
# ② 注册表配置键三层（HKLM / WOW64 / HKCU）
reg query "HKLM\SOFTWARE\软件名" ; reg query "HKLM\SOFTWARE\WOW6432Node\软件名" ; reg query "HKCU\SOFTWARE\软件名"
# ③ 主目录 / 程序
where 主程序.exe  2>nul
# ④ AppData 用户数据 / 更新器目录（Electron/PWA/npm 类软件常留这里）
for %d in ("%APPDATA%\软件名" "%LOCALAPPDATA%\软件名" "%LOCALAPPDATA%\软件名-updater") do @if exist %d echo 残留目录 %d
# ⑤ 服务 / 计划任务 / 开机自启
sc query state= all | findstr /i 软件名
schtasks /query /fo csv /ne | findstr /i 软件名
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" | findstr /i 软件名
```

**验收逻辑（判读方式）：**
- 上面每一项**有输出**＝该项残留；**全部无输出**＝干净。
- **AppData 项按上面"快照 diff"判断，不只看名字。**
- 有残留 → **默认直接清理并复验到空**（卸载=彻底删，不用再回头问要不要删），清理前 `tasklist` 确认不在运行。

**汇报模板（主动给，不等问）：**
```
卸载【干净】/【⚠ 有残留】。
已清除：主程序、卸载项、计划任务…。
残留：%APPDATA%\\xxx（330MB 用户数据，已随卸载连带清理）、注册表键 HKCU\\SOFTWARE\\xxx（已删）→ 全部清空。
```

> 反例：只回"已卸载完成"却不知道主程序、AppData、注册表键还剩什么，就是没按规定自动验收——必须自己用命令查明并写清，才算真的卸载完。

### 6.1 清理残留（卸载后常留，全查一遍）
```bash
# 1) 卸载项 + 配置键（重点）
reg query "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "软件名"
# 2) 应用配置/身份键残留 ——【v1.1 重点，极易漏】
reg query "HKLM\SOFTWARE\软件名"
reg query "HKLM\SOFTWARE\WOW6432Node\软件名"
reg query "HKCU\SOFTWARE\软件名"
#   ↑ 这里藏设备身份/注册 UUID/GUID/设置，卸载器常漏（实测 ToDesk 就藏在 HKLM\SOFTWARE\ToDesk）
# 3) 用户数据残留
dir "%APPDATA%\软件名" "%LOCALAPPDATA%\软件名" 2>nul
# 4) 启动项残留（忘了会自启）
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /s | findstr /i 软件名
# 5) 服务残留（忘了会偷自启）
sc query state= all | findstr /i 软件名
# 6) 计划任务残留（垃圾/流氓软件常在这里自我启）
schtasks /query /fo csv /nh | findstr /i 软件名
# 7) 文件/快捷方式残留
where.exe 主程序名  2>nul
# 8) 内置驱动文件/服务残留（远程/摄像头类，见 2.4/4.5）
```
- 检查到的残留（含 AppData 用户数据）默认一律清理——已卸载，目标就是彻底删除。删前 `tasklist` 确认没在跑；想留一份可先备份。只有用户先前明确要求"保留数据"才暂不删，但仍要标清位置和大小。

> ⚠️ 命中第 2) 条（`HKLM\SOFTWARE\软件名`）说明卸载器没删这一层——它常放**设备身份/登录授权**，**重装会"复用旧身份"**，要就把它连根删掉。

> ⚠️ **管理员权限铁律**：删除 `HKLM` 层的键（`Uninstall\软件名`、`SOFTWARE\软件名`）与 `sc delete 服务` 需要**管理员**。普通权限下会返回"拒绝访问(5)/系统找不到(2)"，**别把"拒绝访问"当成"已删除"误报**。AI 必须用支持提升权限的会话，`reg delete`/`sc delete` 都在管理员下执行。

### 6.2 验证卸载成功
```bash
# 程序和目录没了
dir "C:\Program Files\某软件\某程序.exe" 2>nul    # 为空 = 已删
# 各注册表层无残留（回用§4.4 的建档重查一遍）
# 空间释放
powershell "(Get-PSDrive C).Free/1GB"
```
**确认：命令找不到 / 程序无法打开 / 注册表无残留 / 空间释放 → 才算卸载完成。**

## 七、备份（卸载这类删除操作的第一保障）
- 先备份 `%APPDATA%` 用户数据目录（用户找回/可重装）。
- 卸载大型/绑定软件前，导出注册表卸载项：`reg export "HKLM\...\Uninstall\某软件" backup.reg`，可回退。
- **绝不跳过备份静默卸载重要软件。**
- 删除 `HKLM\SOFTWARE\软件名` 这类注册键前同样**先 `reg export` 导出**，可回滚。

## 八、命令速查表

| 目的 | 命令 |
|---|---|
| 查卸载项 | `reg query "HKLM\...\Uninstall" /s /f 软件名` |
| 查配置键残留 | `reg query "HKLM\SOFTWARE\软件名"` |
| NSIS 静默卸 | `卸载.exe /S` |
| Inno 静默卸 | `卸载.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART` |
| MSI 静默卸 | `msiexec /x 包.msi /qn` |
| 杀进程（卸载前） | `taskkill /IM 进程.exe /F` |
| 清注册表卸载项 | `reg delete "HKLM\...\" /f`（危险，需管理员） |
| 清配置键残留 | `reg delete "HKLM\SOFTWARE\软件名" /f`（危险，需管理员） |
| 清 AppData 残留 | `rd /s /q "%APPDATA%\软件名"`（危险，需用户同意） |
| 查计划任务 | `schtasks /query /fo csv /nh \| findstr /i 软件名` |
| 验证空间 | `powershell (Get-PSDrive C).Free/1GB` |
| 备份注册表 | `reg export "HKLM\..." backup.reg /y` |

## 九、卸载"卸不下 / 困难"的坑
1. 进程还跑着 → 卸载被拦，先 `taskkill /IM xxx.exe /F`。
2. 卸载器带假自保护（杀软 / 装驱动的软件）→ 没法静默，交给官方或引导手动。
3. 乱删目录导致菜单/注册表残留 → 见第六节。
4. 某些软件重装又回来（服务/自启回填）→ 提示用户"删了可能重装又回来"，不是错误。
5. **"配置键没删"当"已卸载完"** → ① 查 `HKLM\SOFTWARE\软件名` 是否还在；② 需要管理员权限删除，权限不够别把"拒绝访问"误当"已删除"。

## 十、操作规范（AI 助手必须遵守）+ 动手前自查

1. **先查后卸**：先 2 章核查，展示信息再动。
2. **危险命令**：`reg delete`、`rd /s /q`、`taskkill`、`sc delete` —— 先备份 + 说清楚 + 用户点头再执行。
3. **用户数据（AppData）默认随卸载一并清掉，除非用户明确要留。**
4. **保护项拒绝**：系统核心 / 硬件驱动 / 杀毒 / 用户依赖，先告知再动手。
5. **卸载后必须清残留 + 验证 + 汇报**：不验证别硬说成功。
6. **不假设**：删前确认软件、路径、权限。
