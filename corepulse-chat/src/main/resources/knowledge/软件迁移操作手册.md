第一章 迁移前必读：核心原则与三大铁律
1.1 一句话理解软件迁移
一个装好的软件 = 一个安装目录 + 一堆"写着它地址"的引用。
迁移 = 把安装目录复制到新盘 + 把所有引用改到新地址 + 验证能跑 + 删除旧目录。

引用包括：

引用类型	在哪里	例子
快捷方式	桌面、开始菜单	桌面上"微信开发者工具.lnk"
注册表	卸载信息、图标路径	HKLM...\Uninstall 下的 UninstallString
环境变量	PATH	命令行工具（如 Git、JDK）
自启动	Run 键、服务、计划任务	开机自动运行的程序
文件关联	注册表	双击 .txt 用哪个程序打开
用户数据	%APPDATA% / %LOCALAPPDATA%	登录状态、缓存（通常不用动）
1.2 三大铁律（违反任何一条都会出事故）
铁律一：复制，绝不剪切/移动
Windows 对正在运行的程序文件有锁，直接剪切必失败；剪切中途断电/报错，旧文件可能损坏。
正确顺序永远是：复制 → 改引用 → 验证 → 删旧。任何一步失败都能回退。

铁律二：先核查再说话
禁止凭记忆回答"软件装在哪、占多大"。必须先用工具查清楚：

安装目录在哪、多大

用户数据（AppData）在哪、多大

有哪些引用（快捷方式/注册表项）

程序是不是正在运行

铁律三：删旧前必须先验证
旧目录只能在"新位置启动成功"之后删除。删了就回不来了。

1.3 迁移的收益判断
迁移一个软件通常释放 0.5~5GB。迁移前告诉用户能释放多少空间，让用户决定。
C 盘可用空间 > 50GB 时，迁移不是紧急需求，但要尊重用户的明确要求。

第二章 第一步：先核查再说话
用户提出"迁移/搬到/换盘"某个软件时，先执行以下核查，把事实摆出来，再谈方案。

2.1 查安装目录和大小
用终端命令（runShellCommand，以下命令均可直接执行）：

text
# 方法一：查注册表卸载信息（最准，能拿到安装位置）
reg query "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "软件名关键字" 

# 方法二：查 Program Files 目录
dir "C:\Program Files" /b
dir "C:\Program Files (x86)" /b

# 方法三：查 AppData 用户数据目录
dir "%LOCALAPPDATA%" /b
dir "%APPDATA%" /b
判断规律：

程序本体：通常在 C:\Program Files 或 C:\Program Files (x86) 下的软件名目录

用户数据：通常在 C:\Users\用户名\AppData\Local\软件名 或 AppData\Roaming\软件名

有的软件全部塞在 AppData\Local（绿色安装），有的全在 Program Files

2.2 查目录大小
text
# 查单个目录大小（注意：du 在 cmd 里不存在，用 PowerShell）
powershell -Command "$s=(Get-ChildItem 'C:\Program Files (x86)\某软件' -Recurse -ErrorAction SilentlyContinue | Measure-Object -Property Length -Sum).Sum; '{0:N2} MB' -f ($s/1MB)"

# 更简单：powershell 查文件夹大小
powershell -Command "{0:N2} GB" -f ((Get-ChildItem '路径' -Recurse -ErrorAction SilentlyContinue | Measure-Object Length -Sum).Sum/1GB)
2.3 查程序是否在运行
text
tasklist | findstr /i "软件进程名"
例如微信开发者工具：tasklist | findstr /i "wechatdevtools"。
如果进程在运行，必须让用户关闭程序（或获得用户同意后由助手关闭），否则复制时会文件锁定失败。

2.4 查引用（快捷方式）
text
# 查桌面和开始菜单快捷方式指向哪里
powershell -Command "$ws=New-Object -ComObject WScript.Shell; Get-ChildItem $env:USERPROFILE\Desktop -Filter *.lnk | ForEach-Object { $s=$ws.CreateShortcut($_.FullName); if($s.TargetPath -like '*软件名*'){ Write-Host $_.FullName; Write-Host 'Target:' $s.TargetPath; Write-Host 'WorkDir:' $s.WorkingDirectory } }"

# 开始菜单（用户级）
powershell -Command "$ws=New-Object -ComObject WScript.Shell; Get-ChildItem $env:APPDATA\Microsoft\Windows\Start' 'Menu -Recurse -Filter *.lnk | ForEach-Object { $s=$ws.CreateShortcut($_.FullName); if($s.TargetPath -like '*软件名*'){ Write-Host $_.FullName; Write-Host 'Target:' $s.TargetPath } }"

# 开始菜单（全局级）
powershell -Command "$ws=New-Object -ComObject WScript.Shell; Get-ChildItem $env:ProgramData\Microsoft\Windows\Start' 'Menu -Recurse -Filter *.lnk | ForEach-Object { $s=$ws.CreateShortcut($_.FullName); if($s.TargetPath -like '*软件名*'){ Write-Host $_.FullName; Write-Host 'Target:' $s.TargetPath } }"
2.5 查引用（注册表）
text
# 卸载项（InstallLocation / UninstallString / DisplayIcon 三个字段最关键）
# 建议使用更精确的关键词，或用 findstr 过滤，避免匹配过多无关项
reg query "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "软件名" 

# 自启动项（Run 键）
reg query "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"

# 文件关联（一般不用动，除非软件是默认打开某类文件的）
assoc | findstr "扩展名"
2.6 核查完毕后的汇报格式
核查完必须向用户汇报（表格形式）：

text
已核查「软件名」的完整情况：
| 项目 | 位置 | 大小 |
|---|---|---|
| 程序本体 | C:\Program Files (x86)\... | 982 MB |
| 用户数据 | C:\Users\123\AppData\Local\... | 3.2 GB |
| 桌面快捷方式 | 有，指向旧路径 | - |
| 注册表卸载项 | 有，UninstallString 指向旧路径 | - |
| 进程 | 未运行 / 正在运行 | - |
| 迁移可释放 C 盘 | 约 982 MB（用户数据可留原地） | - |
然后给出迁移方案和影响，等用户确认后执行。

第三章 第二步：判断软件能不能迁（三类分级）
3.1 A类：可以安全迁移（推荐迁移）
特征：程序本体是独立目录，不依赖系统服务，不注册深度驱动。

绿色软件（免安装版）

Electron / NW.js 应用（微信开发者工具、VS Code、Obsidian 等）

游戏（Steam 库、WeGame 等，游戏平台本身支持迁移）

大部分开发工具（JDK、Node、Python 等，改环境变量即可）

浏览器（夸克、Chrome 等，本体可迁，用户数据建议留原地或单独处理）

3.2 B类：谨慎迁移（能做，但要注意）
特征：依赖注册表深度注册或系统服务。

杀毒软件（如火绒）：有驱动和自保护，迁移极易损坏，不建议，卸载重装更安全

需要安装驱动的软件（虚拟光驱、模拟器增强包）

深度绑定登录态的软件：迁移后需要重新登录（问题不大，但要提前告知用户）

3.3 C类：绝对不迁移
Windows 系统组件（WinSxS、System32、Program Files\WindowsApps 等）

驱动程序（显卡驱动、网卡驱动等，必须用官方安装器）

系统服务型软件（依赖 Windows 服务注册的）

正在被迁移过程中无法停掉的软件

3.4 判断口诀
text
装完不需要管理员权限也能跑 → A类，放心迁
装的时候要装驱动/服务 → B类，谨慎
名字带 Windows / 驱动 / 杀毒 → C类，别动
第四章 第三步：复制（robocopy 详解）
4.1 复制前检查
目标盘有足够空间（至少比源目录大 20%）

目标目录不存在或为空（避免新旧文件混在一起）

软件进程已关闭

4.2 robocopy 标准命令
text
robocopy "C:\旧路径" "D:\新路径" /E /COPY:DAT /DCOPY:T /R:1 /W:1 /MT:16 /NFL /NDL /NP
参数解释：

参数	含义
/E	复制所有子目录（含空目录）
/COPY:DAT	复制文件的数据、属性、时间戳（不复制权限/所有者，避免权限问题）
/DCOPY:T	复制目录的时间戳（保留目录的创建/修改时间）
/R:1 /W:1	失败重试1次、等1秒（加快失败速度，避免卡死）
/MT:16	16线程并行复制（大目录快很多；若系统响应变慢可调低至 /MT:8）
/NFL /NDL /NP	不列文件名/目录名/进度（输出简短，避免撑爆 LLM 上下文）
4.3 复制结果的解读（重要）
robocopy 退出码（命令返回的数值）含义：

退出码	含义	处理
0	无文件复制（目标已一致）	正常
1	成功复制了文件	✅ 正常
2	目标目录有多余文件	正常（不删目标）
3	1+2 组合	✅ 正常
4	发现不匹配	⚠️ 检查
8	复制失败（文件被锁等）	❌ 必须处理，重试或排查
16+	严重错误	❌ 停止，报告
判断方法：输出里看是否有 "ERROR" 字样；退出码 >= 8 就是失败。
大目录（>1GB）复制需要 1~3 分钟，耐心等待命令返回。

4.4 复制完成后验证文件
text
# 对比文件数量（源 vs 目标）
dir "C:\旧路径" /s /b | find /c /v ""
dir "D:\新路径" /s /b | find /c /v ""

# 确认关键文件存在
dir "D:\新路径\主程序.exe"
数量可以不完全相等（个别隐藏文件差异正常），但关键 exe 必须在。

第五章 第四步：改引用（快捷方式 / 注册表 / 环境变量 / 自启动）
复制完成后、删除旧目录前，把所有写着旧路径的地方改成新路径。

5.1 改快捷方式（桌面 + 开始菜单）
快捷方式 .lnk 是二进制文件，不能当文本改，必须用 PowerShell 的 WScript.Shell COM 对象：

text
# 改单个快捷方式（把 旧路径 换成 新路径）
powershell -Command "$ws=New-Object -ComObject WScript.Shell; $s=$ws.CreateShortcut('C:\Users\123\Desktop\软件名.lnk'); $s.TargetPath='D:\新路径\主程序.exe'; $s.WorkingDirectory='D:\新路径'; $s.Save()"
批量改（自动找桌面和开始菜单里所有指向旧路径的快捷方式）：

text
powershell -Command "$ws=New-Object -ComObject WScript.Shell; $old='C:\旧路径'; $new='D:\新路径'; Get-ChildItem $env:USERPROFILE\Desktop,$env:APPDATA\Microsoft\Windows\Start' 'Menu -Recurse -Filter *.lnk -ErrorAction SilentlyContinue | ForEach-Object { $s=$ws.CreateShortcut($_.FullName); if($s.TargetPath -like \"$old*\"){ $s.TargetPath=$s.TargetPath.Replace($old,$new); $s.WorkingDirectory=$s.WorkingDirectory.Replace($old,$new); $s.Save(); Write-Host '已修改:' $_.FullName } }"
注意：修改开始菜单（全局级）快捷方式可能需要管理员权限。如果报错，提示用户以管理员身份运行终端。

5.2 改注册表卸载项（关键！）
卸载项位置（32位软件在 WOW6432Node 下，64位软件直接在 Uninstall 下）：

text
HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\软件标识
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\软件标识
要改的字段：

UninstallString：卸载程序路径（如 ...\卸载软件.exe）

DisplayIcon：图标路径（如 ...\主程序.exe）

InstallLocation：安装位置（如果有）

text
# 查询具体卸载项（先找到软件标识，即注册表子键名）
reg query "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "软件名"

# 【强烈建议】修改前备份该注册表项，以便回退
reg export "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\软件标识" C:\backup_软件名.reg

# 修改（把 old 换成 new；reg add 属于危险命令，会触发确认，必须向用户说明后执行）
reg add "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\软件标识" /v UninstallString /t REG_SZ /d "D:\新路径\卸载软件.exe" /f
reg add "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\软件标识" /v DisplayIcon /t REG_SZ /d "D:\新路径\主程序.exe" /f
注意：

改 HKLM 需要管理员权限，如果命令报"拒绝访问"，告知用户需要管理员权限

卸载项不改也能正常使用软件，但"控制面板卸载"会找不到程序，所以必须改

如果注册表里 InstallLocation 为空字符串，不用管它

5.3 改环境变量 PATH（仅命令行工具需要）
适用：JDK、Node、Python、Git 等命令行工具。改完需要重启终端/软件才生效。

text
# 查看当前用户 PATH
reg query "HKCU\Environment" /v Path

# 修改（把旧路径段替换为新路径段）
powershell -Command "$p=[Environment]::GetEnvironmentVariable('Path','User'); $p=$p.Replace('C:\旧路径','D:\新路径'); [Environment]::SetEnvironmentVariable('Path',$p,'User')"
5.4 改自启动项（Run 键）
如果软件的启动命令在 Run 键里写了旧路径：

text
# 查看
reg query "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" /v 软件名
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" /v 软件名

# 修改
reg add "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" /v 软件名 /t REG_SZ /d "\"D:\新路径\主程序.exe\"" /f
5.5 不需要改的
软件内部配置里的路径（软件自己会在设置里重新找，或首次启动提示）

用户数据目录（AppData 里的东西不动，软件启动时会自动找到，因为 %APPDATA% 没变）

文件关联（软件重新启动时会自己重新注册）

第六章 第五步：验证新位置能跑
改完引用后，必须启动一次验证，不能跳过：

text
# 1. 确认新路径主程序存在
dir "D:\新路径\主程序.exe"

# 2. 从新路径启动（会打开软件窗口，告知用户正在验证）
start "" "D:\新路径\主程序.exe"

# 3. 等几秒后确认进程运行，且可执行路径是新路径
tasklist | findstr /i "进程名"
powershell -Command "Get-CimInstance Win32_Process | Where-Object { $_.Name -like '*进程名*' } | Select-Object ProcessId,ExecutablePath | Format-List"
验证成功的标准：

进程存在

ExecutablePath 显示为 D:\新路径...（而不是 C:\旧路径...）

软件窗口正常打开（让用户看一眼是否正常）

建议额外验证核心功能：对于开发工具，尝试打开一个项目；对于浏览器，尝试访问一个网页；对于普通软件，检查菜单/设置是否可点——比"仅启动成功"更有说服力

验证失败的排查：

报"找不到 DLL/组件"→ 复制不完整，检查 robocopy 输出是否有 ERROR

双击没反应 → 快捷方式 TargetPath 没改对，检查快捷方式

启动后马上闪退 → 软件有硬编码路径（少见），考虑卸载重装方案

验证成功后，把软件窗口关掉（如果用户不打算现在用），进入下一步。

第七章 第六步：确认无误后才删旧目录
7.1 删除前检查清单（全部满足才删）
□ 新位置启动成功，进程可执行路径是新路径
□ 用户已知晓并同意删除旧目录
□ 所有快捷方式、注册表引用都已指向新路径
□ 旧目录没有正在被占用的文件
7.2 删除命令（危险命令，必须先获得用户确认）
text
# 删除旧目录（危险命令，必须先向用户展示命令原文并获得确认，confirmed=true 后执行）
# 必须带 /q：本助手在非交互终端执行命令，不带 /q 时 rd 的 Y/N 确认提示无人应答，命令会卡死失败；
# 安全确认由助手的"危险命令用户确认"机制保证（已在执行前完成），不依赖命令行交互
rd /s /q "C:\旧路径"
7.3 删除后确认
text
# 确认旧目录已不存在
dir "C:\旧路径" 

# 统计释放的空间
powershell -Command "(Get-PSDrive C).Free/1GB" 
7.4 汇报格式
text
✅ 迁移完成！
| 项目 | 结果 |
|---|---|
| 软件 | 微信开发者工具 |
| 新位置 | D:\新路径 |
| 释放 C 盘 | 约 982 MB（迁移前可用 X GB → 迁移后 X+0.96 GB） |
| 验证 | 从新路径启动成功 ✅；核心功能验证通过 ✅ |
| 用户数据 | 保留在 C:\Users\...\AppData（未动） |

8.5 静默安装/卸载（替代方案用，需谨慎）
安装包类型	静默安装	静默卸载
NSIS（.exe，多数国产软件）	安装包 /S	卸载程序 /S
Inno Setup（.exe）	安装包 /VERYSILENT /SUPPRESSMSGBOXES /NORESTART	卸载程序 /VERYSILENT
MSI（.msi）	msiexec /i 包.msi /qn	msiexec /x 包.msi /qn
指定安装目录	NSIS: 安装包 /S /D=D:\路径（注意 /D 必须最后且无引号）
Inno: /VERYSILENT /DIR="D:\路径"	-
第九章 常见软件迁移案例
9.1 微信开发者工具（小程序开发工具）
实际情况（2026-08 实测）：

程序本体：C:\Program Files (x86)\Tencent\微信web开发者工具（约 1GB）

用户数据：C:\Users\用户名\AppData\Local\微信开发者工具（登录态、项目缓存，通常不动）

项目代码：用户自己管理，一般在别的盘，永远不要碰用户项目目录

迁移步骤：

核查：确认进程未运行（tasklist | findstr /i "wechatdevtools"）

复制：robocopy "C:\Program Files (x86)\Tencent\微信web开发者工具" "D:\WeChatDevTools" /E /COPY:DAT /DCOPY:T /R:1 /W:1 /MT:16 /NFL /NDL /NP

改引用：

桌面"微信开发者工具.lnk"和开始菜单两个 .lnk（启动+卸载），Target/WorkDir 改 D 盘

注册表卸载项 HKLM\SOFTWARE\WOW6432Node\...\Uninstall 下微信开发者工具项的 UninstallString、DisplayIcon 改 D 盘

验证：start "" "D:\WeChatDevTools\微信开发者工具.exe"，确认进程路径是 D 盘

删旧：确认后 rd /s /q "C:\Program Files (x86)\Tencent\微信web开发者工具"

注意：用户数据目录留在原地即可，软件会自动找到（%LOCALAPPDATA% 未变）

9.2 夸克浏览器
实际情况：

程序本体 + 更新器：C:\Program Files\QuarkUpdater 和 C:\Program Files (x86)\QuarkUpdater

用户数据：C:\Users\用户名\AppData\Local\Quark（缓存、下载，占大头）

配置：C:\Users\用户名\AppData\Roaming\Quark（很小）

迁移注意：

程序本体可迁（步骤同 9.1 模板），但用户数据建议留在原地——浏览器登录态、书签迁移风险高

如果目的是释放 C 盘，更推荐：程序本体迁移 + 引导用户在浏览器设置里把下载目录/缓存目录改到 D 盘

更新器目录（QuarkUpdater）要一起迁，否则更新时找不到程序

9.3 通用迁移模板（任何 A 类软件都适用）
text
1. 核查 → 2. 关进程 → 3. robocopy 复制 → 4. 改快捷方式+注册表
→ 5. 从新路径启动验证 → 6. 用户确认 → 7. 删旧目录 → 8. 汇报
9.4 游戏迁移
Steam：Steam 客户端内"设置 → 存储 → 添加驱动器 → 移动"，或直接把游戏目录移到新库目录后用 Steam 重新识别

第十章 替代方案：卸载重装（什么时候才用它）
10.1 什么情况用卸载重装
B 类软件（装驱动/服务的，如火绒、虚拟光驱）——优先推荐此方案

迁移后验证失败、且排查无果的软件

软件本身支持安装器选择路径，且迁移复杂度太高（引用太多）

10.2 ⚠️ 卸载重装的静默方式（高风险操作，必须谨慎）
原则上，优先引导用户通过控制面板手动卸载，再手动安装到新路径。 这是最安全的方式。

若用户明确要求全自动执行，AI 助手可尝试静默卸载重装，但必须遵守以下前置条件：

告知风险：向用户明确说明——静默卸载可能无提示地删除用户数据（登录态、配置、存档等），且不同安装包的静默参数不通用，参数错误可能导致安装失败

备份用户数据：在执行静默卸载前，确认并备份用户的配置/数据目录位置（通常在 %APPDATA% 或 %LOCALAPPDATA% 下）

获得用户确认：用户明确同意承担上述风险后，方可执行

静默卸载重装命令参考：

text
# 1. 找到卸载程序（注册表 UninstallString 就是它）
reg query "HKLM\SOFTWARE\WOW6432Node\...\Uninstall" /s /f "软件名"

# 2. 静默卸载（NSIS 型）
"C:\路径\卸载程序.exe" /S

# 3. 下载或定位安装包，静默安装到 D 盘
安装包.exe /S /D=D:\目标路径

# 4. 验证
tasklist | findstr /i "进程名"
10.3 卸载重装的额外提醒
静默参数因安装包类型而异——先 安装包.exe /? 或 /h 或 /? 查看帮助确认参数

执行前确认安装包确实存在，且路径正确

部分软件卸载后需要重启才能完全清除残留，告知用户可能需要重启

第十一章 安全红线（绝对禁止触碰）
以下内容任何情况下都不允许迁移/删除/修改：

红线	原因
C:\Windows 整个目录	系统核心
C:\Windows\WinSxS	系统组件存储，动一点系统就坏
C:\Windows\Installer	系统安装缓存，删了软件无法卸载/修复
C:\Program Files\WindowsApps	UWP 应用（必须用系统设置迁移）
pagefile.sys / hiberfil.sys	虚拟内存/休眠文件（要用系统设置移动，不是复制）
用户桌面/文档/图片/聊天记录	个人数据，只能建议用户自己移动，绝不代删
杀毒软件、驱动程序	有驱动保护，迁移必坏
System Volume Information	系统还原点
另外：

迁移过程中发现目标盘空间不足，立即停止，报告用户

任何一步失败，旧目录还在，可以回退——这是复制而非移动的意义

复制大目录时命令可能执行几分钟，属于正常现象，不要判定为卡死

第十二章 AI 助手执行规范（必须遵守）
12.1 流程强制顺序
text
用户要求迁移 → 核查（2.1~2.6）→ 汇报事实 → 分类定级（第三章）
→ 得到用户确认 → 关进程 → 复制（第四章）→ 改引用（第五章）
→ 启动验证（第六章）→ 汇报 → 用户同意 → 删旧（第七章）→ 汇报结果
任何一步都不能跳过。 特别是：不核查就下结论、不验证就删旧，都是严重错误。

12.2 命令确认规则（配合系统安全机制）
只读查询命令（reg query、dir、tasklist、powershell 查询）：直接执行

robocopy 复制：非危险命令，会话授权后免确认；首次需向用户说明"将复制 X GB 到 D 盘"

改注册表（reg add）、删目录（rd /s）、杀进程：危险命令，必须先向用户解释影响、展示命令原文，获得确认后以 confirmed=true 执行

命令返回"【需要用户确认】"时：解释 → 展示原文 → 等用户确认 → 重新调用

12.3 与用户沟通规范
全程简体中文，通俗易懂，不堆术语

迁移前：表格汇报核查结果 + 迁移方案 + 能释放多少空间

迁移中：告诉用户"正在复制（约 X GB，需要 1~3 分钟）"等进度预期

迁移后：表格汇报新位置、释放空间、验证结果

用户问"能不能迁/怎么迁"时，先核查再回答，禁止凭印象回答软件位置和大小

用户要求一站式完成时，能自动执行的绝不推给用户手动操作；只有需要用户拍板（如删除旧目录）才停下来问

12.4 常见错误自查（回答前先对照）
□ 我是否用命令核查了软件的真实位置和大小？（不是凭记忆！）
□ 我是否先复制、验证，而不是直接建议卸载重装？
□ 我是否把删除旧目录这个动作留到了验证之后？
□ 我是否把所有引用（快捷方式/注册表）都改了，而只改了快捷方式？
□ 我是否把用户数据和个人文件与程序本体区分开了？
□ 我是否向用户汇报了能释放的空间？
□ 删除旧目录时，我是否使用了带 /q 的 rd /s /q 命令（非交互终端下不带 /q 会卡死），并在执行前已获得用户确认？
