## 一句话理解启动项

> 开机自启动 = 电脑每次启动时，系统自动帮你运行的一些程序。
> 禁用启动项 = "让某个程序开机时别再自己偷偷跑"。
> 但你删掉的是"启动开关"，不是程序本身——删了程序照样能在桌面/开始菜单手动打开。

**核心原则：**
1. **先备份再改动** —— 一切改动前把原始内容存下来，出问题能一键还原。
2. **改完必须验证** —— 删/禁完要重新查一遍，确认真的生效，不能光靠"我以为成功了"。
3. **危险动作前先解释** —— 删注册表、停服务这些动作有破坏性，动手前要讲清楚会怎样、展示命令原文，获得用户同意再执行。

## 第一章 自启动的来源（4 种，缺一不可）

**新手最大的坑：以为自启动就藏在注册表 Run 键里。实际有 4 个来源，漏查任何一个就会出现"我明明禁了怎么还启动"。**

| 来源 | 位置 | 谁在管理 | 说明 |
|---|---|---|---|
| **1. 注册表 Run 键(用户级)** | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | 不需要管理员 | 装过自家自启的软件最常写这里 |
| **2. 注册表 Run 键(系统级)** | `HKLM\Software\Microsoft\Windows\CurrentVersion\Run` | **需要管理员** | 写系统的软件(驱动/办公全家桶)写这里 |
| 3. 启动文件夹 | 用户 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`<br>公共 `C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp` | 放 `.lnk` 快捷方式 | 放在这里的快捷方式开机就运行 |
| **4. Windows 服务** | 注册表 `HKLM\SYSTEM\CurrentControlSet\Services` | **需要管理员** | ⚠️ **任务管理器启动页不显示**，最容易被漏掉 |

> ⚠️ **第 4 种（服务）是漏网之鱼重点**：像爱思助手、迅雷、很多国产软件，不自上进 Run 键，而是注册成一个"服务"。你在 Windows 的"启用任务管理器→启动"或"设置→应用→启动"里**根本看不到它**，但它照样默默开机自启动。用户说"我禁了怎么还在"，八成是这个原因。

**所以排查/禁用启动项，必须把"Run 键 + 启动夹 + Windows 服务"三处全扫一遍，缺一不可。**

## 第二章 一键扫描所有启动项（动手第一步）

**永远先查、后改。禁止凭印象说"这软件有没有自启"、凭印象动手。**

用 Python 一次性列出三大来源（注册表 Run + 启动夹 + 服务），输出结果一眼看清：

```python
import winreg, os, ctypes
from ctypes import wintypes

def enum_run(hive, path, label):
    print(f"=== {label} ===")
    try:
        k = winreg.OpenKey(hive, path)
        i = 0
        while True:
            try:
                n, v, _ = winreg.EnumValue(k, i)
                print(f"  {n} = {v}")
                i += 1
            except OSError:
                break
    except OSError as e:
        print(f"  [打不开: {e}]")

enum_run(winreg.HKEY_CURRENT_USER, r"Software\Microsoft\Windows\CurrentVersion\Run", "注册表 Run （当前用户 HKCU）")
enum_run(winreg.HKEY_LOCAL_MACHINE, r"Software\Microsoft\Windows\CurrentVersion\Run", "注册表 Run （系统级 HKLM）")

for csidl, label in [(7,"开机文件夹（用户）"), (0x18,"开机文件夹（公共）")]:
    buf = ctypes.create_unicode_buffer(260)
    ctypes.windll.shell32.SHGetFolderPathW(None, csidl, None, 0, buf)
    print(f"=== {label}: {buf.value} ===")
    if os.path.isdir(buf.value):
        for f in os.listdir(buf.value):
            print(f"  {f}")

print("=== Windows 服务 （自动启动的）===")
# 用 sc 列出服务更稳（在 cmd 里跑）
```

（上面只读，无副作用，可直接运行；服务部分下面用 `sc` 单独查，见 4.1。）

## 第三章 判断：能不能动？（保护项白名单）

**有些启动项绝对禁止删/禁**，删了你把用户系统搞坏。这条 `never-disable` 死名单必须内置，命中就拒绝操作并说明原因：

| 名称 | 为什么不能禁 |
|---|---|
| `ctfmon.exe` | 中文输入法核心，禁了没法切换输入法 |
| `sysdiag` / 杀毒软件全家 | 安全软件，禁了电脑裸奔 |
| `SecurityHealth` / Defender | Windows 安全中心 |
| `RtkAudUService` | 声卡/耳机服务，禁了可能没声音 |
| 显卡/网卡/声卡驱动相关 | 驱动不能禁，会出问题 |

**操作前自问：`这软件是不是系统/驱动/安全类？是 → 拒绝并解释；不是 → 可操作但先备份。**

## 第四章 场景：禁用某个软件的启动项（核心）

### 4.1 先确认它是怎么启动的（Run 键？启动夹？服务？）

```bash
# 在注册表 Run 键里找（对 HKCU 和 HKLM 都用）：
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /s
reg query "HKLM\Software\Microsoft\Windows\CurrentVersion\Run" /s

# 在启动夹里找：
dir "%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup"
dir "C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp"

# 查明是服务在启动（这步很多人漏！按软件名/路径搜）：
sc query state= all | findstr /i "软件名"        # 或
powershell "Get-CimInstance Win32_Service | Where-Object {$_.StartMode -eq 'Auto'} | Select Name,DisplayName,PathName"
```

### 4.2 按找到的类型，禁用

**A) 注册表 Run 键里的项 ——（删除该值名，软件本身不动，下次开机不自动启动）**

```bash
# 禁用 = 删除该值。先备份原始值（用第二章脚本读出来，记录到备份文件），然后：
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v "ValueName" /f   # HKCU 直接执行
reg delete "HKLM\Software\Microsoft\Windows\CurrentVersion\Run" /v "ValueName" /f   # HKLM 需管理员，会触发确认
```

> ⚠️ 改 **注册表如果连 HKCU**，一般直接能写；**HKLM 需管理员**，命令报"拒绝访问"就提示用户"需要管理员权限"，不要静默失败。

**B) 是启动文件夹里的快捷方式 —— 把 `.lnk` 剪切到备份文件夹（不要删）**

```bash
# 移动到备份目录，既可禁用又可随时还原
move "%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\某某.lnk" "C:\Users\xxx\startup_backup\"
```

**C) 是服务 —— 把服务改成"手动启动"（软件不被启动，但手动打开仍可用）**

```bash
sc config 服务名 start= demand   # 改成手动（注意 start= 后面有个空格）
sc stop 服务名                    # 立即停掉正在跑的
# 对应用户提示：有些软件（爱思助手等）在重装/升级时会把自己服务改回自动，到时需再处理。
```

> ⚠️：禁服务会**改**底层配置，危险动作，操作前务必说"把某某服务改为手动手控，平时关但不删，重装可能复原"，用户点头再执行。
> 拒绝访问时，同注册表方法：要管理员权限。

### 4.3 验证（必须做）

禁用后**重新查一遍**，确认该项确实不见了/服务变成手动：

```bash
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v "Value" 2>&1   # 应显示找不到
sc query 服务名 | findstr START_TYPE                                              # 显示 'DEMAND' 即手动
```

**验证通过才算完成，别只报"已禁用"。**

## 第五章 恢复启动项（还原操作）

**拿之前备份出来的内容写回即可：**

```bash
# 恢复 Run 键值 —— 原来是 name = 原始路径，把它 `reg add` 回去：
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v "名字" /t REG_SZ /d "原始路径" /f
# 恢复启动夹快捷方式 —— 把 .lnk 从备份目录剪切回去
move "C:\Users\xxx\startup_backup\某某.lnk" "%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\"
# 恢复服务 —— 改回自动 + 启动
sc config 服务名 start= auto
sc start 服务名
```

## 六、自启动"挡不住"的常见坑

1. **软件会"回填"**：许多软件（uTorrent、迅雷、夸克…）每次启动时会**主动把自启项写回注册表**。你禁了，它下次开又回来了。→ 处理：禁掉它的启动项后**提示用户**"这软件可能会自己加回来，禁了它在启动页看不到，但过几天可能又被反向装回"。这不算失败，是软件行为。
2. **藏在服务里**：见第一章，忘了查服务就"禁了还在启动"，先扫服务。
3. **用户权限不足**：HKLM / 服务的操作在普通权限下会失败 → 明确告知"需要管理员"，不要假装成功。

## 七、命令速查表

| 目的 | 命令 |
|---|---|
| 列出用户 Run 项 | `reg query "HKCU\...\Run"` |
| 列出系统 Run 项 | `reg query "HKLM\...\Run"` |
| 列出自动启动服务 | `Get-CimInstance Win32_Service | ? StartMode -eq Auto` |
| 查某值 | `reg query "...Run" /v 名字` |
| 禁 Run 项（HKCU） | `reg delete "...Run" /v 名字 /f` |
| 禁 Run 项（HKLM） | `reg delete "...Run" /v 名字 /f`（需管理员） |
| 禁启动夹项 | 把 `.lnk` `move` 到备份目录 |
| 禁服务 | `sc config 服务名 start= demand`（管理员） |
| 恢复服务 | `sc config 服务名 start= auto` |
| 验证 Run | `reg query "HKCU\...\Run" /v 名字` |
| 验证服务 | `sc query 服务名 | findstr START_TYPE` |

## 八、操作规范（AI 助手/执行代理必须遵守）

1. **先查后改**：任何启动相关操作前，先跑第二章扫描，把现状展示给你，再谈要不要动。
2. **危险动作三连**：删注册表值、`sc config`、动启动文件夹——⚠️ **改前先备份 + 展示命令原文 + 获得用户同意** 再执行。
3. **备份放哪**：`C:\Users\<用户名>\startup_backup\`,禁用前把 Run 键全部值 dump 到 `日期_启动项备份.txt`。
4. **保护项拒绝**：命中 `ctfmon.exe`/杀毒/驱动/声卡，直接拒并解释，不动。
5. **完成必验证 + 汇报**：禁用后重画验证，汇报"我禁了谁 / 怎么做的 / 验证结果 / 想恢复随时反"。
6. **绝不假设**：禁止凭记忆说"它没启动"，用命令查证。
