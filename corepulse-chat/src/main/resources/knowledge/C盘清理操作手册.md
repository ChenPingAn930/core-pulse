## 一句话理解 C 盘清理

> C 盘被占满 = 三大类东西在占地方：**①系统/软件必须用的（Program Files、Windows、页面文件）②软件自己堆的缓存垃圾（临时文件、更新包、日志、缩略图）③用户自己的材料（下载、文档、桌面文件）**。
> **清理 = 把 ②里的垃圾删干净、把 ③里用户不要的大文件清掉，绝不碰 ①。**
> 清理从来不是"把占用清到 0"（那不现实，系统/软件本来就要占空间），而是"把**该扔的垃圾**扔干净，把**留着没用的**挪走/删掉"。

**核心原则（本手册的"魂"，AI 助手必须内化）：**

1. **安全是红线，红线之上的东西必须清干净** —— 先划清"绝不能碰"的底线，底线之外凡是安全可删的垃圾/缓存，**默认都清、清到干净为止**，不要只清一两个文件夹就停手"走个过场"，也不要因为怕事就把一眼能识别的垃圾也留着。
2. **绝不碰红线之下的一根毛发** —— 系统目录、正在运行的程序、属于别人的文档，哪怕能腾出再大空间也一个字不能动。安全 > 干净。**违背红线的清理请求直接拒绝并解释原因。**
3. **先查后清，别闭眼扫** —— 先看 C 盘占用全貌、先找到"到底是谁在占空间"，再决定清什么。禁止凭印象直接乱删。
4. **危险动作先确认，安全动作放心干** —— 只有碰到"有风险/不可逆/删了就回不来"的（清空回收站、Windows 更新缓存、Windows.old、休眠文件）才需用户点头；纯安全的缓存临时文件**无需逐项反复确认**，直接清。
5. **清完必须验证 + 主动汇报** —— 清理前后都用 `getDiskSpace`/磁盘工具实打实量一遍，回复结尾**必须给出"清理前 → 清理后 → 释放了 X GB"+ 清了什么**的验收结论，禁止凭空报数、禁止甩一句"清理完成"就结束。

## 一、先查再动：动手前只做两件事

**禁止一上来就 `del`。先摸清家底，再决定清谁。**（这两步都是只读、无副作用，可直接做）

### 1.1 看 C 盘空间占用（全览）

```bash
# 看 C 盘总空间 / 已用 / 可用（最常用）
powershell "Get-PSDrive C | Select-Object Used,Free,@{n='FreeGB';e={[math]::Round($_.Free/1GB,2)}}"
# 只看可用（单位 GB）
powershell "(Get-PSDrive C).Free/1GB"
```

### 1.2 找 C 盘的大头（用"热点探测"，别全盘扫描）

> ⚠️ **实测忠告（2026-08-26 真机验证）**：**不要用 `Get-ChildItem C:\ -Recurse` 之类去"全盘递归量大小"**——在真实用户 C 盘上要 **3–4 分钟甚至更久，工具会超时**（git-bash 的 `du` 更慢）。正确打法：**只逐点探测下面的已知热点区**，每个单独量大小，快（一起探测 10 秒内完成）又直接能决策。

把下面这段存成 `.ps1` 跑一遍，或逐条跑、只看自己关注的热点（**全部只读，不删任何东西**）：

```powershell
$ErrorActionPreference='SilentlyContinue'
function SizeOf($p){
  if(Test-Path -LiteralPath $p){
    $s=(Get-ChildItem -LiteralPath $p -Recurse -File -Force -EA SilentlyContinue | Measure-Object -Property Length -Sum).Sum
    if($s){ '{0,-58} {1,8:N2} GB' -f $p,($s/1GB) } else { '{0,-58} {1,8}' -f $p,'0 B' }
  } else { '{0,-58} {1,8}' -f $p,'(无)' }
}
SizeOf "$env:TEMP"                       # 用户临时文件（A 档大头，常几 GB）
SizeOf "C:\Windows\Temp"                 # 系统临时
SizeOf "C:\Windows\SoftwareDistribution\Download"   # Windows 更新缓存（B 档）
SizeOf "C:\$Recycle.Bin"                 # 回收站（B 档）
SizeOf "C:\Windows.old"                  # 旧系统（B 档，存在才有）
SizeOf "C:\ProgramData\Microsoft\Windows\WER"       # 错误报告（A）
SizeOf "$env:LOCALAPPDATA\CrashDumps"    # 崩溃转储（A）
```

> 如果某热点很大（比如 `$env:TEMP` 好几 GB），按热度决定：A 的对应的直接进第三部分清理，B 的拿去给用户确认。**你不确定哪个目录大时，就逐条探测上面这 7 个命中项，别去扫全 C 盘。**

**单独量某个目录的大小**（比如你想确认 `C:\Users\<用户>\AppData\Local` 下哪个子目录占得最多）：

```powershell
# 想细看的大目录，改成你要看的路径（注意：递归量超大目录也慢，只对单个子目录用）
powershell "$s=(@(Get-ChildItem -LiteralPath 'C:\Users\<用户>\AppData\Local' -Recurse -File -Force -EA SilentlyContinue) | Measure-Object -Property Length -Sum).Sum; if($s){'{0:N2} GB' -f ($s/1GB)}else{'0 B'}"
# 列某个目录下各一级子目录各自多大（排序前 15，揪出大头）
powershell "Get-ChildItem -LiteralPath 'C:\Users\<用户>\AppData\Local' -Directory -Force -EA SilentlyContinue | ForEach-Object { $s=(@(Get-ChildItem -LiteralPath $_.FullName -Recurse -File -Force -EA SilentlyContinue) | Measure-Object -Property Length -Sum).Sum; [PSCustomObject]@{Dir=$_.Name;GB=[math]::Round($s/1GB,2)} } | Sort-Object GB -Descending | Select-Object -First 15 | Format-Table -AutoSize"
```

> 第 3 行那条下钻命令主要看**缓存在 AppData 里的大头**（Electron/浏览器/IDE 的缓存目录各几 GB），对定位"该清哪"很有用；它是递归扫单个子目录树，**比全盘快得多**（实测 40 秒内），可接受。

> 💡 判断方法：看到一个较大的目录，先看它是"软件缓存"（名字含 `Cache`、`Temp`、`Crashpad`、`Logs`、`-updater`、`electron` 等 → 是垃圾，可安全清，即 A 档）还是"软件本体 / 用户数据"（`Program Files`、`.git`、`Documents` 等 → 别乱动，即 C 档红线，见第二章节）。

## 二、清理清单：三类分级（安全→红线）

> 这是手册**最核心的表**。AI 清理 C 盘时照这张表逐档推进：**先把 A 档清干净，再逐项确认 B 档，C 档一行都不许碰。**

| 级别 | 是什么 | 怎么处理 | 要不要问 |
|---|---|---|---|
| **A 安心清（垃圾）** | 明确的缓存/临时/日志/缩略图，删了软件会自动重建、绝不丢数据 | **放心直接清干净**，不用逐项问 | ❌ 不用确认 |
| **B 谨慎清（要控制）** | 能清但删了会丢用户东西 / 影响功能 / 不可逆（回收站、更新缓存、旧系统） | 说清楚影响 + 拿用户点头再清 | ✅ 必须先确认，清前备份 |
| **C 绝对不碰（红线）** | 系统文件、运行中的软件、正在写入的数据、属于用户的不可再生资料 | **拒绝 + 解释**，哪怕空间再紧 | ⛔ 永远不碰，不做预案 |

> ⚠️ **给 LLM 的分寸**：**A 档不用等确认就叫你清，叫你别动不动打断用户问"要不要清临时文件"** —— 那是废话，直接清。**B 档再如何都必须确认**，哪怕用户说"随便清"。**C 档连问都不要问，直接拒绝**。这样既"清得干净"，又不辜负"安全"。

### A 档（安全垃圾 · 放心清干净）

这些都是"删了能自动重建 / 本来就是临时用途 / 丢了也不影响任何数据"的缓存，**属于不能偷懒的部分，一键清干净：**

```bash
# ① 当前用户临时目录 %TEMP%（缓存高发区，往往几百 MB 到几 GB）
del /f /s /q "%TEMP%\*.*" 2>nul
# ② 系统临时目录（只清"能删的"，别删 Windows 正在用的 —— 被占用文件自动被跳过）
del /f /s /q "C:\Windows\Temp\*.*" 2>nul
# ③ 浏览器缓存（Chrome 系 / Edge）
rd /s /q "%LOCALAPPDATA%\Google\Chrome\User Data\Default\Cache" 2>nul
rd /s /q "%LOCALAPPDATA%\Microsoft\Edge\User Data\Default\Cache" 2>nul
# ④ 应用程序自身的小缓存（Electron/网页类软件最典型）
rd /s /q "%LOCALAPPDATA%\*\Cache" 2>nul
rd /s /q "%LOCALAPPDATA%\*\Cache_Data" 2>nul
# ⑤ 缩略图/资源管理器缓存
del /f /q "%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*.db" 2>nul
# ⑥ Windows 错误报告（WER）与内存转储
rd /s /q "C:\ProgramData\Microsoft\Windows\WER" 2>nul
rd /s /q "%LOCALAPPDATA%\CrashDumps" 2>nul
rd /s /q "C:\Windows\Minidump" 2>nul
```

> ⚠️ 其中 ② `C:\Windows\Temp` **需要管理员权限**才能枚举/删除：非管理员执行会提示"拒绝访问"，**这代表没清成（不是已清除）**——要么用可提权的会话清，要么明确告诉用户"系统临时目录需管理员权限"再跳过它，不要误报成功。

> ⚠️ **A 档铁律**：上面这些**都是"删了会自动重建"的缓存，一律清干净、不要留一半**。清的时候如果某些文件被占用删不掉（提示"正被另一进程使用"），是被系统/软件锁住的**正在用的缓存**，这种跳过即可（删它反而危险），但**绝大部分都能清**。清完用 §1.1 复验一次空间真正变了。

### B 档（挺大的但要点权衡 · 需确认）

| 项目 | 是什么 | 怎么清 | 注意 |
|---|---|---|---|
| **回收站** | 删过的文件待清占位 | `powershell Clear-RecycleBin -Force` | 清空=彻底删用户已删的文件，**需确认** |
| **Windows 更新缓存** | 系统更新下载/解压的旧补丁包 | `cleanmgr` 勾"Windows 更新清理"，或 `del SoftwareDistribution\Download\*` | 影响将来更新**重打**，可删，**需确认** |
| **Windows.old**（升级残留旧系统） | 常见 10–30GB | `cleanmgr` 勾选"以前的 Windows 安装"，或 `rd /s /q C:\Windows.old` | 彻底删旧系统，**需确认 + 备份要数据** |
| **休眠文件 hiberfil.sys** | 常 4–16GB | `powercfg /h off`（自动删 hiberfil.sys） | 会**禁用休眠/快速启动**，**需确认** |
| **下载目录/桌面的大文件** | 用户传的素材/安装包 | 让用户确认后删/搬迁 | 属于"用户资料"，**必须让用户自己拍板** |
| **组件存储旧备份**（DISM 清理） | WinSxS 累积补丁备份 | `Dism /Online /Cleanup-Image /StartComponentCleanup` | 删掉旧的补丁备份不可回滚，**需确认** |

### C 档（红线 · 永不碰）

**以下任何东西，拿命都不能碰 —— 删了系统崩溃 / 开机失败 / 数据链全毁：**

- `C:\Windows` 全部（**根目录更是整个系统**）：`System32`、`SystemApps`、`WinSxS`、`Fonts`、`Boot`、`INF` 等。
- `C:\Program Files`、`C:\Program Files (x86)` 下的软件本体（**正在天天运行的软件**）。
- 页面文件 `pagefile.sys`、休眠文件 `hiberfil.sys` —— **绝不直接删文件**，如需回收空间走 B 档的 `powercfg /h off`（休眠文件）统一处理。
- `C:\ProgramData`/系统级写权限目录里被**正在服务的软件**锁定的东西。
- 用户的文档、图片、桌面文件（`C:\Users\用户\Documents`、`Pictures`、`Desktop`、`.git` 等）—— **除非用户明确点了某一堆**，碰就算误删。
- 非 C 盘的更不能碰（检测工具常挂 C、D 盘），**清理永远只针对 C 盘**。

## 三、各档位的实战清理流程（照着做）

> 追求**"安全前提下的干净"**：把 A 档全部清干净 + B 档逐项确认后全清掉 + C 档一行不碰，就是"清得很干净、又很安全"。

### 3.1 清理前建档（对"怎么验收干净"很有用）

清理开始前，先调 `getDiskSpace`（或 `powershell (Get-PSDrive C).Free/1GB`）记录 **C 盘当前可用空间**，作为后面验证释放量的基线。

### 3.2 第一步：先清 A 档（不确认，直接清干净）

跑一遍 §2 的 A 档命令，把临时目录、浏览器缓存、WER、缩略图、废弃 crash dump 清空。注意执行时如果某命令报"文件被占用"（软件正在用），跳过被占的文件即可，但**别因为一个报错就偷懒整个文件夹只删了一半**。

### 3.3 第二步：找大头、确认 B 档（找"最大的垃圾"）

用 §1.2 扫出占空间最大的目录，定位到大文件/大目录后：
1. 如果是 `%TEMP%`、缓存之类 → 已在上一步清掉了；
2. 如果是 `回收站`、`SoftwareDistribution\Download`、`Windows.old`、`下载/桌面的安装包`这类 **B 档**（删除有影响、或属用户资料）→ **停下**，把"它是什么、占多少、删了有什么影响/不删又继续占"告诉用户，等确认后执行；
3. 如果是 C 档软件本体/系统 → 明确告诉用户这个不能动，别碰。

### 3.4 第三步：复核空间 + 主动汇报（不报数不算完）

清除完，用 `powershell (Get-PSDrive C).Free/1GB` 量一遍清后空间，跟 §3.1 的清前对比，把**释放了多少、清了哪些**写进最终回复。**没给这个验收结论就不算结束。**

## 四、安全铁律与红线（LLM 动手前必须过一遍）

1. **只清 C 盘，绝不动 D 盘/其他分区**（即使 D 盘也快满了，那是迁移的事，不是"清理"的范围）。
2. **绝不用 `format`、`del` 系统目录、清 `C:` 整个盘**。遇到想这么做的请求 → 拒绝。
3. **一切删除必须可确认 / 可回收**：凡是会永久删掉东西的（清空回收站、删 Windows.old、删休眠文件）→ **先讲后果再让用户点头**；凡是用户资料 → 问用户。缓存/日志这些会自动重建的 A 档 → 不用问。
4. **不清正在运行的软件的内存**：删除 `Program Files` 下被占用的 dll / exe 会被系统拒绝（锁），别硬删、也别把"被占用删不掉"误当成功。
5. **权限不够别看 `拒绝访问` 就当"已删"**：删系统层的东西没有管理员会报 5，那是没删掉，不是删成功了。
6. **停在这个思路的根上**：空间 > 系统能稳定。宁可少清一点，也不要误删系统文件把电脑弄挂。**判断不出干不干净？宁可保守不乱下重手。**

> ⚠️ **一条反常识但重要的提醒**：清完空间后不要像卸载一样"扩大战线"到注册表/启动项。C 盘清理是**磁盘层面**的事；要清理注册表/启动项/装垃圾软件，先停一下确认方向（这属于《启动项管理手册》《软件卸载操作手册》的范畴），**别在清理 C 盘的上下文里顺手去动了别的系统配置。**

## 五、危险命令速查表

| 动作 | 命令 | 系统权限 | 是否可逆 |

| 组件存储清理 | `Dism /Online /Cleanup-Image /StartComponentCleanup` | 管理员 | ⚠️ 删补丁备份不可逆，需确认 |

> 危险动作（上面 ❌/⚠️ 的）动之前，把命令原文 + 后果展示给用户，点头再执行（系统「确认环节」是硬规则）。

## 六、清理完成后的验证（必须做）

```bash
# C 盘可用空间（清理前后各跑一次，对比释放了多少）
powershell "(Get-PSDrive C).Free/1GB"
```

**验收判据（给 LLM）**：清理后 `Free/1GB` **比清理前明显更大**（通常几 GB 起步，看机器脏不脏；清理 A 档一般能释放 4–20GB），系统能正常进（软件能跑、界面没报错）。**空间没变大 → 说明扫到的是被占用的缓存、或漏了大头，别急着报"已清理完成"，回头再定位大头继续清（如 Windows.old、回收站、更新缓存）。**

**验收反馈模板（结尾必须给的结论）：**
```
清理前 C 盘可用：X GB
清理后 C 盘可用：Y GB（释放了 ~Z GB）

已清理（A 档）：临时文件、浏览器缓存、Windows 错误报告、缩略图… （约 Z1 GB）
按你确认清除了（B 档）：回收站 / 更新缓存 / 下载安装包…（约 Z2 GB）
没动（C 档红线）：系统文件、Program Files 本体、文档图片 —— 一个没碰。
```

> ⚠️ **LLM 诚实铁律**：`释放了多少`一定是拿 `getDiskSpace` 前后两次真实数值算出来的差，**不能拍脑袋报个数字**。清完发现没释放多少，就要老实说"这机器本身垃圾不多 / 大头是系统文件不能动"，而不是瞎报个好听的数字。（后端有审计/追踪，会看你是不是真调了工具再去填数。）

> ⚠️ **数值铁律（清单里每一个数字都必须实测，禁止估算占位）**：给用户列"每个目录占多少 GB"时，**每一个数都必须来自 `SizeOf`/测量后的真实结果，不允许用"约 X–Y GB"这种估计范围去冒充实测**。**测不到 / 需要提权的**（系统临时目录、休眠文件、更新缓存等）要如实写"需提权实测"或"**未测量**"，**绝不能编一个区间占位**；回收站、更新缓存、下载、桌面这些**明明能测的，必须先真测再报**，不许凭印象。宁可少写一个数，也不能写一个假数。**"东西找对了，数字填错了"同样是不合格**——项目分类对不能拿来掩盖数值造假。

## 附录 · 常见热区量级锚点（参考，量纲不用于填数）

> **用途**：给 LLM 一个"在陌生机器上先往哪儿看、每个常见热区大概什么量级"的方向感，避免漏清或瞎猜。**锚点只是"提醒别漏"的参考，绝非填数依据——每个数照样必须对当前机器实测（见 §六 数值铁律）。** 下表是 2026-08-26 在一台真机（工作机，含 NVIDIA 显卡、JetBrains 系、多个国产 Electron 软件）上实测出的量级。

| 热区 | 量级锚点（参考） | 提示 |
|---|---|---|
| 用户临时目录 `%TEMP%` | 常 1–5 GB | A 档高发区，必测 |
| 各软件 `*-updater` 更新缓存 | 合计常 1–5 GB（本例 15 个目录=4.96G） | 单目录几十~几百 MB；A 档可清，但注意"小写/大写"别名目录别累加两次 |
| **NVIDIA 着色器/安装缓存** | 常 3–9 GB（本例 8.94G） | A 档安全清，**极易被低估**——见到 `AppData\Local\NVIDIA` 一定量一下 |
| JetBrains 全家 | 可达 10–15 GB+ | 含项目索引/配置，只有 `caches`/`logs` 片段算 A 档，别整目录当垃圾 |
| Windows 更新缓存 `SoftwareDistribution` | 通常 ≈0–几百 MB | 本例仅 ~0.05G，**别高估**成"更新占用很多" |
| 回收站 `$Recycle.Bin` | 常几百 MB–几 GB | 可统实测（本例 1.74G），**别一句"未测"就跳过** |
| 休眠文件 `hiberfil.sys` | 约内存的 0.4–1 倍 | 本例 13.6G；`powercfg /h off` 可释放，需确认 |
| QClaw 等双大小写目录 | 注意大小写不重计 | Windows 文件系统大小写不敏感：`QClaw`/`qclaw` 常是同一目录，**只能算一次** |
| 开发/模型环境（`.lmstudio`、Conda 等） | 配置目录通常不大 | 绝大多数模型在非 C 盘（如 `E:\gguf`），**别把全盘模型全算进 C 盘**；`.lmstudio` 多为配置（~3.5G） |
| 用户 Documents/Pictures/Music | 用户资料，C 档 | 属"用户自己的材料"，永远不自动碰，只在用户点名后清/搬 |

> 一句话：**锚点负责"提醒你该往哪看"，实测负责"告诉你要填什么数"——两者别混。**
